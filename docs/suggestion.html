1 · Audit — what's great & what's in the way

Read-only: no edits yet

✅ Strengths to keep (don't break)

  • Pure pi-model, no fallback — zero deps, no PI_API_BASE/auth.json, no external fetch. Audited via appendEntry("jev", …).
  • Parallel 5 Questions in 1 tool — jev_calibrate 8 fields = 1 LLM turn for Score+Noul (matches Jev blog: parallel barely adds cost).
  • Gate extracted — harness/gate.ts:evaluateGate() is pure + testable; 33 tests pass.
  • Tool-chain — calibrate → plan → git with auto-commit on agent_settled + auto-init — great agent ergonomics.
  • Cache + phase — JevCache (TTL 300s, 200 cap) + phaseOf() idle/awaitingCalibrate/awaitingPlan/ready.
  • Zero-deps distribution — pi: extensions ["src/index.ts"] + allowImportingTsExtensions is idiomatic pi.

⚠️ Gaps that tax agents / tokens / humans

  • Ceremony tax: every prompt injects calibration instruction even for read README.md or hi — LLM pays ~300 in / 150 out tokens for no signal.
  • Two-turn chain mandatory: calibrate then plan = 2 LLM tool calls serially even when plan is obvious. No jev_calibrate+plan batch.
  • Planner blind to modern tools: plan action enum misses smart_read/smart_bundle/cext_batch/fetch_content — agent must break its own plan to be efficient.
  • No execution state: plan has no progress cursor, no done/skip, no resume — agent re-asks or freelances after turn 2.
  • Cost-blind widget: shows policy:high risk:0.80 phase:ready — not actionable; no token/latency budget.
  • Git monolith: jev_git with 6 actions in one schema hurts tool-calling accuracy; status spawns 2–3 exec git in parallel.
  • UX dumps JSON: /jev:status prints raw JSON.stringify(policy, null,2) — wall of text, not a card.

2 · 5-Step Algorithm — applied to this harness

Question → Delete → Simplify → Accelerate → Automate
Step 1 — Question

Challenge every requirement

Does every prompt need calibration? Does every complex task need a separate plan turn? Does git need 6 actions in one tool? Ask until the “why” breaks.

Step 2 — Delete

Remove what shouldn't exist

Delete trivial-prompt calibration, delete the forced 2nd plan turn (merge when obvious), delete git monolith sprawl, delete JSON-dump status — before optimizing any of it.

Step 3 — Simplify

Optimize what remains

One cohort of smart tools in plan enum, one git exec per status, one status card, one cache key strategy, one threshold config path.

Step 4 — Accelerate

Make it faster

Coalesce calibrate+plan in one LLM turn, cache semantically (hash, not just slice), compress state, parallelize nothing the LLM must do serially.

Step 5 — Automate

Automate only after above

Plan cursor auto-advances, auto-commit squashes, widget auto-shows next step, telemetry auto-records — no automation of ceremony we just deleted.

How each suggestion maps to the 5 steps (traceability)

Every suggestion card below carries a 5-Step chip: Question / Delete / Simplify / Accelerate / Automate. Rule enforced: no card is “Au” without passing Q→D→S→A. Example: “Merged jev_calibrate+plan” is Q (do we need 2 turns?) → D (delete mandatory separation) → S (one schema) → A (1 LLM turn saved) → Au (auto-advance cursor).

AF-01

Trivial-prompt bypass — delete calibration that shouldn't exist · Q → D

Problem: before_agent_start injects buildJevInstruction for every prompt, even read foo, ls, hi. LLM forced to emit JSON for zero-risk turns — wasted tokens + latency, and teaches agent to ignore the harness.

Proposal
Add isTrivialPrompt(prompt) gate: if prompt length < 60 or matches ^(read|list|show|cat|ls|hi|help)\b and no write intent, skip calibration entirely and set lastPolicy=low, risk≈0 ephemeral (not cached). Only complex prompts trigger tool call.

export function isTrivialPrompt(p:string){
  const s=p.trim().toLowerCase();
  if(s.length<40) return s.split(/\s+/).length<6;
  return /^(read|list|show|cat|ls|hi|help|status)\b/.test(s)
      && !/(write|edit|delete|deploy|migrate|refactor)/.test(s);
}
// in before_agent_start: if(isTrivial(p)) return;
// ephemeral policy: {complexity:{level:"low",score:0.12}, needsPlan:{p:0.05}}

PR-02

Semantic cache key — hash, not slice · Q→S

Cache key is state.slice(0,2000) — two prompts differing only after char 2000 collide; two prompts with same intent but different phrasing miss. Both waste or corrupt.

Proposal
Key = sha256(normalize(state)) where normalize = lowercase + trim + collapse whitespace + sort file lists. Keep LRU 200, but add semantic secondary key: if normalized prompt overlaps ≥90% tokens, reuse with warning.
